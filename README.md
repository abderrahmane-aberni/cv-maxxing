# Resolve — AI CV & job-fit analyser

Upload a CV (PDF) and a job description. Get back a structured skills-gap
report, an ATS-style keyword match score, and before/after bullet rewrite
suggestions — generated by an LLM constrained to a fixed JSON schema.

This is Project 2 of a learning roadmap focused on applied AI engineering:
the point isn't a chat demo, it's turning messy real-world input (a PDF)
into a reliable pipeline with structured, validated output.

## Architecture

```
resolve/
├── backend/        FastAPI app (API, PDF parsing, Gemini client, DB)
├── frontend/        Streamlit UI
├── prompts/         Versioned prompt text + changelog (see below)
├── tests/           pytest suite (schema validation, retry logic, PDF parsing)
└── .github/workflows/ci.yml   Runs the test suite on every push/PR
```

Flow: PDF upload → text extraction (`pypdf`, falling back to `pdfplumber`)
→ one Gemini call with `response_schema` set to the exact Pydantic model
the API returns → validated result stored in a database → returned to the
frontend/API caller.

## Why a `/prompts` folder

The system prompt sent to Gemini lives in `prompts/v1_system_prompt.md`,
not inline in Python. `prompts/CHANGELOG.md` records *why* each version
changed — which failure mode or bad output it was trying to fix. Prompt
engineering is iterative; most portfolios show the final prompt and none
of the reasoning that got there. This folder is that reasoning.

## Setup

Requires Python 3.12+ and a free Gemini API key.

```bash
# 1. Get a free key (no card required) at https://aistudio.google.com/apikey

# 2. Backend
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # then paste your GEMINI_API_KEY into .env
uvicorn app.main:app --reload

# 3. Frontend (separate terminal)
cd frontend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run streamlit_app.py
```

Backend API docs: http://localhost:8000/docs
Frontend UI: http://localhost:8501

### Or with Docker

```bash
cp backend/.env.example backend/.env   # then add your key
docker compose up --build
```

## API

- `POST /api/analyze` — multipart form: `cv_file` (PDF), `job_description`
  (text, 20+ chars). Returns the structured report plus token usage.
- `GET /api/history?limit=20` — recent analyses (score, filename, model).
- `GET /api/history/{id}` — full stored result for one analysis.
- `GET /health` — liveness check.

## Testing

```bash
pip install -r backend/requirements.txt
pytest tests/ -v
```

The Gemini client's retry-on-invalid-JSON logic is tested with a mocked
client (no real API calls, no cost). Runs automatically on every push via
GitHub Actions (`.github/workflows/ci.yml`).

## Cost tracking

Every response includes `usage.input_tokens`, `output_tokens`, and
`estimated_cost_usd`. The cost will show as `0.0` while
`COST_PER_1K_INPUT`/`COST_PER_1K_OUTPUT` are left at their defaults — which
is correct, since this project runs on Gemini's free tier. Set those env
vars to the current per-1K-token price if you want the field to mean
something (e.g. if you outgrow the free tier, or just want to demonstrate
cost-awareness with realistic numbers).

## Known limitations (honest, on purpose)

- Scanned/image-only PDFs aren't supported — there's no OCR step, only
  text-layer extraction.
- No hand-labeled accuracy eval set yet (the plan calls for one — a small
  set of CV/JD pairs with expected scores — as a good next step).
- `CORS` is wide open (`allow_origins=["*"]`) because this is a demo
  running locally; tighten it before any real deployment.
- The Gemini model ID is set in `backend/.env.example`
  (`gemini-3.5-flash-lite` as of Oct 2026). Google renames/retires model
  IDs periodically — if calls start failing with a "model not found"
  error, check https://ai.google.dev/gemini-api/docs/models for the
  current cheapest Flash/Flash-Lite model name and update `GEMINI_MODEL`.
